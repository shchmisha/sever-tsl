Локальный контур `native_image`: видео → устойчивые кадры отдельных листов → проверка качества → чтение изображений моделью → сверка реквизитов по разным кадрам того же листа → JSON, CSV, HTML и трасса шагов.

Каждый пригодный лист передаётся мультимодальной модели как реальные изображения. Установленный reader V7 `native-source-images-model-authority-v5.2`, схема `native-image-model-authority-v5.1` и агент `fresh-model-selected-source-crops-v4` сначала свежим вызовом определяют поворот, затем дают модели инструмент выбора настоящих нативных участков того же кадра. Финальный ответ `submit_reading` содержит форму и реквизиты. Для известных форм `visible_text` содержит собственный заголовок/шапку; буквальные строки ролей и значений записываются в `field.evidence_text`. Для `unknown` сохраняется более широкая буквальная транскрипция. Код проверяет структуру ответа, контрактный набор полей и привязку доказательств к отправленным изображениям; семантические фильтры заголовка, даты, номера и ролей не используются. Отдельного классификатора и предварительного Tesseract нет. Для подтверждения типа и каждого поля нужны согласующиеся доказательства из двух разных исходных кадров того же листа; повороты и фрагменты одного кадра не считаются независимыми видами. Фиксированного ограничения числа кадров на лист нет: остаются пригодность входа и общий бюджет.

Сохранённые ответы распознавания не подставляются и не перечитываются как новый результат. Новый запуск требует новых фактических вызовов модели; `image-reading-evidence/` хранит отправленные изображения, их SHA/геометрию и ответы только как доказательства. Эталонные значения в inference не передаются.

## Запуск

Нужны Python 3.12+, FFmpeg/FFprobe и настроенная мультимодальная модель. `native_image` не требует платформенного OCR. Для прежнего режима `ocr_guided` на macOS нужны Apple Vision и компилятор Swift (`xcode-select --install`, если инструменты отсутствуют), на Linux — Tesseract с `rus` и `eng`.

```bash
uv sync --frozen --extra dev --python 3.13 --no-editable
```

Зависимости воспроизводятся по `uv.lock`; эта команда устанавливает пакет вместе с CLI. После изменения исходников выполните её повторно с `--reinstall-package sever-tsl`. Для сборки устанавливаемого пакета выполните `uv build --wheel`: исходник `sever/native/vision_ocr.swift` входит в wheel и компилируется локально при первом запуске Apple Vision. FFmpeg и платформенный OCR устанавливаются отдельно от Python-пакета.

Локальный режим без внешнего API-ключа:

```bash
export HARNESS_PROVIDER_KIND=local
export HARNESS_MODEL_BASE_URL=http://127.0.0.1:8090/v1
export HARNESS_MODEL_NAME=qwen38-27b-q6
export HARNESS_VISION_MODEL=qwen38-27b-q6
export HARNESS_DOCUMENT_READER=native_image
export HARNESS_MODEL_TIMEOUT=600
export HARNESS_MAX_OUTPUT_TOKENS=8192
.venv/bin/sever process /absolute/path/video.mp4 --out runs/native-demo \
  --model qwen38-27b-q6 --max-requests 2000 --max-tokens 40000000 --refresh-cache
```

В локальном режиме `native_image` выбирается по умолчанию. Для явного воспроизведения прежней схемы задайте `HARNESS_DOCUMENT_READER=ocr_guided`; в remote-режиме это прежнее значение по умолчанию. Неверное название режима отклоняется при настройке.

Следующие способы с внешним провайдером относятся к историческому `ocr_guided`. API-ключ используется только процессом запуска. Для интерактивного запуска его можно ввести скрыто через `getpass`, без сохранения на диск:

```bash
.venv/bin/python tools/run_pilot.py /absolute/path/video.mp4 --out runs/demo
```

При заранее настроенном окружении:

```bash
.venv/bin/sever process /absolute/path/video.mp4 --out runs/demo --max-requests 100 --max-tokens 150000
.venv/bin/sever evaluate runs/demo/results.json analysis/provisional-ground-truth.json --out runs/demo/metrics.json
.venv/bin/sever serve
```

В remote-режиме `HARNESS_MODEL_BASE_URL` по умолчанию `https://routerai.ru/api/v1`; обязательный ключ — `HARNESS_MODEL_API_KEY`. Прежняя классификация по OCR и чтение реквизитов используют по умолчанию `openai/gpt-4.1-mini`; настройки — `--model` и `HARNESS_VISION_MODEL`. В `native_image` модель получает действительные изображения каждого пригодного листа сразу, без OCR или ожидаемых значений. Оба режима используют OpenAI-compatible Chat Completions, структурированный JSON через Pydantic AI, общий бюджет и учёт расхода. Обработка видео и выбор кадров выполняются локально. Текст документов рассматривается как данные, включая напечатанные команды.

Для API со скрытым вводом ключа используйте `.venv/bin/python tools/serve_local.py` (ключ остаётся в памяти процесса). Локальный API открывает Swagger по `http://127.0.0.1:8080/docs`. `POST /v1/jobs` принимает JSON с `source_path` — абсолютным путём к видео на компьютере сервера. Возвращает идентификатор задания; `GET /v1/jobs/{id}` — состояние, `/results` — JSON, `/fields.csv` — таблицу. Выполняется одно задание одновременно; состояния сохраняются на диске. API предназначен для локального исследовательского контура.

```bash
curl http://127.0.0.1:8080/health
curl -X POST http://127.0.0.1:8080/v1/jobs \
  -H 'Content-Type: application/json' \
  -d '{"source_path":"/absolute/path/video.mp4","max_requests":100,"max_tokens":150000}'
curl http://127.0.0.1:8080/v1/jobs/JOB_ID
curl http://127.0.0.1:8080/v1/jobs/JOB_ID/results
curl http://127.0.0.1:8080/v1/jobs/JOB_ID/fields.csv
```

Задание проходит состояния `queued`, `processing`, `completed` / `completed_with_errors` либо `failed`. Каталог заданий задаётся `SEVER_RUNS_DIR`, по умолчанию `runs/`. API допускает до 2000 запросов и 40 млн токенов для локального задания; для remote-задания пределы остаются 400 запросов и 500 тыс. токенов. Превышение remote-предела отклоняется до постановки в очередь. При исключительной блокировке оценки новое задание получает HTTP 423; уже принятый worker ждёт освобождения общей блокировки. Ошибка настройки модели или недоступное хранилище возвращает HTTP 503 до очереди. `/health` показывает `model_backend`, `model_name`, `document_reader` и fingerprint реализации; исправный сервис сам по себе не доказывает распознавание.

## Артефакты одного прогона

* `results.json`: источник и SHA-256, кандидаты листов, интервалы, выбранные исходные кадры, качество, типы, поля, доказательства и ошибки.
* `fields.csv`: одна строка на обязательное поле; исходное и нормализованное значение, статус, уверенность, ссылки на кадры.
* `report.html`, `report-assets/`: просмотр результатов с JPEG-превью и ссылками на полноразмерные исходные кадры. В `native_image` для каждого сохранённого чтения, включая `unknown`, показаны `observed_form`, буквальный `visible_text` из ответа модели и ошибки. Таблицы значений, предложенных моделью на каждом фактически прочитанном кадре, отделены от итогового подтверждения по двум кадрам.
* Промежуточный `report.html` обновляется после каждого фактического чтения и завершения страницы: статус «Обработка продолжается», ссылка на `partial-results.json`, без финального CSV, автоматическое обновление каждые 10 секунд. При остановке после трёх подряд ошибок чтения или исчерпании бюджета checkpoint и отчёт сохраняют все обработанные страницы/ошибки со статусом `failed`; отчёт показывает «Обработка остановлена» и перестаёт обновляться.
* `selected-pages.json`, `video/video-analysis.json`, `video/frames/`: автоматический выбор и исходные полноразмерные кадры.
* `additional-frames/`: дополнительные виды того же листа, извлечённые по необходимости; JPEG, исходные PTS и параметры кодирования сохраняются в метаданных кадра.
* `classifications.json`: совместимое имя артефакта решений о типе; в `native_image` это результат общего чтения изображения, отдельного запроса классификатора нет.
* `image-readings/`: чтения каждого кадра листа, транскрипция и сведения о подтверждении по нескольким кадрам.
* `image-reading-evidence/`, `image-reading-evidence/image-panels/`: фактически отправленные JPEG-контексты и выбранные моделью нативные PNG-фрагменты, SHA источника и изображений, геометрия/повороты, версия схемы, новые ответы, вызовы увеличения и явные отказы без изображения. Это запись доказательств без повторного использования ответов. Имя `image-reader-cache/` относится к прежним сборкам.
* `trace.jsonl`: фактические запросы и ответы модели, отправленные изображения, результаты проверки и сверки, кэш и расход. В начале `native_image` фиксируются отсутствие локального OCR и отдельного классификатора.
* `partial-results.json`: источник/SHA, `status`, время обработки, завершённые листы и незавершённое текущее чтение при прерывании.
* Только `ocr_guided`: `ocr/`, `ocr-cache/`, общий `vision-cache/` и `inn-cache/` сохраняют прежний OCR, чтения фрагментов и проверки ИНН. В `native_image` сверка ИНН пока отмечается `not_performed`, без заявления о проверке ФНС.

Значения имеют статусы `recognized`, `not_present`, `unreadable`, `conflict`. Неразрешённое поле содержит `normalized_value=null`. В `native_image` доказательство содержит буквальную транскрипцию модели, идентификатор исходного кадра и координаты действительно отправленного изображения или фрагмента; `region_index=null`. Это координаты изображения, а не автоматически найденные границы слов. Сохраняются SHA, масштаб и преобразование изображения в исходный кадр. В прежнем `ocr_guided` доступны также ссылки на реальные OCR-области. Уверенность OCR/модели не является измеренной точностью. Модели задано раскрывать явную ссылку «он же» только по видимым реквизитам на том же листе с сохранением обеих строк доказательства.

Для кандидата сохраняются основной и близкие кадры того же интервала. Прямое чтение начинается с основного пригодного изображения и продолжается на других пригодных видах без фиксированного числа кадров. `unknown` на первом кадре не запрещает чтение следующих. Модель определяет собственные реквизиты листа; код связывает доказательства с его исходными кадрами и сравнивает чтения двух разных кадров. Значения, различающиеся после сравнения допустимого оформления, сохраняют `conflict`; большинство кадров не разрешает спор, кроме одного ограниченного правила для номеров и дат (с 18.10.2026): если не менее трёх разных кадров прочитали одно и то же значение, а каждое отличающееся прочтение встречается на одном кадре, отличается не более чем на три символа и таких кадров не более трети от согласных, поле получает согласованное значение со статусом `recognized`; отличающиеся прочтения сохраняются в `field_confirmations.strong_agreement.dissent`. Названия, адреса и утверждения о пустом поле под это правило не подпадают. Модель может перечитать спорные поля совместно по свежим исходным изображениям, сохранив все прежние ответы. Оборотные стороны остаются отдельными кандидатами: в предоставленных видео встречается оборот с другим номером. Границы листов приблизительны; точные PTS сохраняются.

Локальный `quality_gate` явно отклоняет недоступное изображение, почти чёрный или равномерный кадр, слишком малое изображение и подтверждённое сильное размытие без мелких деталей. Если основной кадр отклонён, выбирается пригодный соседний; если отклонены все, кандидат остаётся в результатах с ошибкой качества и в знаменателе оценки. Белая бумага, обрезанный край и цветовой признак возможной руки сами по себе не служат причиной отказа. Пройденная проверка не доказывает читаемость всех реквизитов.

## Агентный подход и расход

Ручные проходы по реальным кадрам сохранены в `analysis/agent-footprints.jsonl` и файлах разметки. Они служат историей разработки. В текущей V7 форму, роль и значение читает сама модель по изображению; программные регулярные выражения для решения этих семантических задач удалены.

`native_image` по умолчанию выполняет свежий вызов выбора поворота, затем до восьми запросов агента на одном исходном кадре. Агент получает один уменьшенный JPEG-контекст и через `zoom_source` выбирает до восьми настоящих PNG-фрагментов без изменения нативного масштаба. Последний запрос оставлен для `submit_reading`; лишний параллельный вызов увеличения возвращает явное `no_image_returned=true` и записывается отдельно от доказательств. Каждый фактический запрос учитывается в общем бюджете и трассе; автоматических повторов запроса провайдеру нет. Неопределённый/невалидный ответ о повороте допускает новое чтение прежнего набора изображений; ошибка бюджета или провайдера не подменяется fallback. Код проверяет структуру, точный набор обязательных полей и происхождение доказательств; решение о форме, датах, номерах и ролях принимает модель. Форматирование при сверке названий/адресов учитывает кавычки и точки сокращений, сохраняя разные слова, цифры и исходные значения; например, «корп.» и «соор.» не объединяются. Форматированное значение может сохраняться отдельно без изменения статуса. Сверка двух разных исходных кадров не заменяет независимую оценку точности. Скрытые рассуждения не запрашиваются.

В `native_image` читаются контекст и фрагменты одного исходного изображения в нескольких ориентациях; они не увеличивают число независимых подтверждений. Есть общие лимиты запросов, токенов, вывода и размера входа. Исчерпание бюджета явно отражается в checkpoint, без заявления о подтверждении полей. Доказательства связаны с исходными пикселями, SHA отправленных изображений, геометрией, моделью, endpoint, схемой и версией инструкции; сохранённые ответы не используются для повторного распознавания. Ошибочные запросы учитываются; HTTP 400/401/402/403 останавливают пакет. В командах CLI оставлен `--refresh-cache`, в запросах API — `refresh_cache=true`; прямое чтение всегда заново вызывает модель. Тексты ошибок провайдера и ключи не попадают в артефакты. Локальный inference имеет billing `local_inference` с нулевой оплатой внешнему API; токены всё равно считаются. Исторический `ocr_guided` сохраняет отдельный OCR и его кэш; remote-стоимость хранится отдельно.

В `ocr_guided` напечатанный ИНН извлекается из собственного блока стороны без исправления цифр, проверяется локально и отдельно сверяется с публичным сервисом ФНС `egrul.nalog.ru`. Сохраняются статусы `matched`, `mismatch`, `ambiguous`, `unavailable`, время и источник; лимит — до десяти уникальных проверок на пакет. В новой схеме `native_image` отдельно подтверждённые ИНН сторон пока не извлекаются для реестра, поэтому `inn_verification.status=not_performed` и `configuration.verify_inn=false`. Регистрация не заявляется проверенной. Название и адрес документа реестр не перезаписывает.

```bash
  --out runs/reference-final --max-requests 5 --max-tokens 100000
```

В каталоге изображений нужны полные страницы `ocr-page-1.png` … `ocr-page-4.png` (также принимается JPEG). В проверке использованы исходные встроенные изображения PDF без дополнительного уменьшения; эталонные значения сохраняются отдельно. Инструмент требует ключ провайдера, использует общий бюджет: один запрос классификации и до четырёх запросов чтения целевых форм. Его временные отметки — искусственные индексы страниц; детекция кадров и качество съёмки по этому прогону не оцениваются.

Независимая предварительная разметка содержит видимые интервалы листов, типы, прочитанные поля, исходные кадры и неопределённости; `customer_approved=false`. Для новой сборки подготовлены [расширенный эталон JSON](analysis/ground-truth-expanded-provisional.json), [таблица CSV](analysis/ground-truth-expanded-review.csv) и [страница проверки HTML](analysis/ground-truth-expanded-review.html). Для передачи сотруднику подготовлена [переносимая таблица с встроенными изображениями](analysis/ground-truth-expanded-review-portable.html), работающая без каталога проекта. Сотрудники Заказчика должны проверить значения и принять разметку; договорный эталон пока не согласован.

Сопоставление выполняется один к одному по временной метке основного выбранного кадра; повторный показ листа считается отдельным видимым интервалом, а не новым уникальным документом. В `candidate_coverage` сохраняется временное покрытие. `frame_document_detection_rate` измеряет пригодность только конкретных независимо просмотренных кадров, привязанных к источнику; для остальных читаемость не выдумывается. Просмотр исходных 88 основных кадров не распространяется автоматически на новые дополнительные виды. Индикаторы полного листа, бликов и перекрытий показываются отдельно с неопределёнными значениями там, где подтверждения нет.

Пропуски входят в знаменатели точности целевых типов и размеченных полей. Для четырёх целевых типов есть отдельная точность; корректный отказ `unknown` считается отдельно, сбой OCR, извлечения или совместной проверки формы/полей правильным отказом не считается. E2E по полностью размеченным целевым листам сохраняет пропуски и ошибочные типы в знаменателе. Дополнительно выводится консервативная нижняя граница по всем целевым листам с числом неразмеченных: неразмеченный лист не объявляется измеренной ошибкой извлечения. Лишние кандидаты учитываются отдельно. Метрики на PDF-примерах отделяются от метрик на реальной съёмке.

Сравнение учитывает регистр, пробелы, варианты кавычек, явно заданные сокращения организационно-правовой формы и оформление пунктуации в названиях/адресах. Слова, значимые символы и цифровые части адреса сохраняются; ведущие нули номера сохраняются. Варианты чтения неоднозначных латинских/кириллических символов допускаются только через `accepted_variants` конкретного размеченного поля.

В объём входят четыре типа и исследовательская обработка предоставленной выборки. Промышленная эксплуатация, интеграция с 1С, приложение водителя, ручная верификация и SLA в ТЗ этого этапа не входят. Для договорной приёмки нужны согласованная тестовая выборка и правильные значения от Заказчика.


## Съёмка и применимость следующего этапа

На предоставленных роликах основная трудность — несколько одновременно видимых
листов: крупный заголовок на сложенном листе может относиться к другой странице.
Для устойчивого результата следует показывать один развёрнутый лист, оставлять
в кадре его края и шапку, держать телефон параллельно плоскости бумаги и сохранять
неподвижный вид на 1–2 секунды перед переворотом. Пальцы следует держать за полями,
свет направлять так, чтобы блик не перекрывал реквизиты. Форму с мелким текстом
лучше показывать ближе, сохраняя весь блок требуемых реквизитов.

Для решения о следующем этапе нужны отдельные видео с ТОРГ-12 и ТрН, согласованная
разметка типов/значений и читаемости выбранных кадров, затем повторный прогон на
новых пакетах документов. Исторические результаты Apple Vision на macOS не
переносятся на сервер: прямое чтение изображений локальной Qwen проверяется отдельным
свежим прогоном 11 полных видео. Внедрение в рабочий процесс, доступы, нагрузка и приёмка
интеграций относятся к следующему согласованному этапу.

## Просмотр исторических отчётов

```bash
.venv/bin/python tools/build_review_table.py
.venv/bin/python tools/build_delivery.py \
  --runs-dir runs/closing --truth analysis/ground-truth-expanded-provisional.json
.venv/bin/python -m http.server 8769 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8769/runs/closing/report.html` для просмотра сохранённого
исторического результата. Повторное распознавание из сохранённых ответов не
используется. Независимый review связан с SHA и конкретными кадрами;
для новых видео его нужно выполнить заново. `build_review_table.py` воспроизводит
CSV и HTML для проверки Заказчиком. `build_delivery.py` собирает сохранённые
результаты и расходы без модельных запросов; отсутствие результата остаётся
явным незавершённым прогоном. Сверка ФНС имеет отдельный срок действия кеша.

Историческую сводку можно собрать отдельно:

```bash
.venv/bin/python tools/build_delivery.py \
  --runs-dir runs/mvp --truth analysis/provisional-ground-truth.json
```

Привязку исходного независимого просмотра к этой разметке воспроизводит
`tools/bind_usability.py`.

Покрытие ТЗ и условные ограничения сохранены в `analysis/spec-compliance.json`.
Исходные DOCX/PDF/MP4 не изменялись.
