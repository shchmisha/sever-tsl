# Север ТСЛ: сервер и клиентское тестирование

## Действующий клиентский кабинет

С 11.10.2026 активна `/opt/sever-tsl/releases/20261011-customer-trial-v1`.
Внешний адрес: **https://185.130.214.240/**. Доступ защищён HTTPS и общим
паролем одной команды заказчика. Локальный файл выдачи доступа —
`.private/customer-trial-access.txt` (права 0600, исключён из Git).
Пароли не помещать в документацию, журналы или аргументы команд.

Кабинет принимает MP4/MOV/M4V/MKV/AVI/WebM до 4 ГиБ и 60 минут;
проверяет контейнер и длительность, сохраняет загрузку и запускает новое
задание с новым UUID. Очередь — один обработчик, максимум два активных
задания команды и четыре по порталу. Состояния, отчёты, исходные кадры,
CSV/JSON и замечания сохраняются после закрытия вкладки. Замечания и
предложенные значения хранятся отдельно и не меняют ответ модели.

Все участники команды видят общие загрузки. Исторические исследовательские
прогоны через этот кабинет недоступны. Публичный nginx обращается только
к `sever-portal` на `127.0.0.1:8082`; API `8080`, модель `8090` и прежний
просмотрщик `8081` остаются на loopback. `X-Sever-User` всегда перезаписывается
nginx после Basic Auth. Не открывать порт 8082 напрямую и не проксировать
внешним пользователям `/srv/sever/runs` или исходный `/v1/jobs`.

Распознавание осталось на Qwen3.8-27B Q6. Из прежних Python-файлов изменён
только `api.py`: потолок локального задания поднят до 4000 запросов;
удалённый провайдер по-прежнему ограничен 400. Клиентские задания получают
4000 запросов / 40 млн токенов и до 300 кандидатов листов. Это квоты,
не гарантия завершения; достижение предела листов явно обозначается как
неполный охват. Новая версия API сохраняет время и путь задания, отмечает
прерванные перезапуском задания ошибкой и исключает второй процесс
обработчика через `/srv/sever/runs/.api-worker.lock`.

Fingerprint: `3ecd20d45b879619aad83000806d7e85607172b97498a8d78f838d41feb5eb65`.
Клиентский портал хранит SQLite и загрузки в `/srv/sever/customer`.
Данные распознавания — в `/srv/sever/runs/{uuid}`. Для неопределённой
отправки (`submission_uncertain`) сначала проверить журнал/API; автоматически
повторно распознавание не запускать. При перезапуске API исходные частичные
артефакты сохраняются, новый запуск требует нового UUID.

Службы: `sever-tsl`, `sever-model`, `sever-portal`, `nginx`.
Конфигурация внешнего входа — `deploy/customer-nginx.conf`, служба портала —
`deploy/sever-portal.service`. Сертификат `/etc/letsencrypt/live/sever-customer-ip/`
получен Certbot 5.8.0 по профилю shortlived. Проверка продления запускается
дважды в день через `sever-certbot-renew.timer`; dry-run и reload nginx
прошли. [Официальная инструкция для сертификата IP](https://letsencrypt.org/2026/03/11/shorter-certs-certbot).

При развёртывании не перезапускать выполняющееся распознавание. Сначала
проверить отсутствие queued/processing и остановленный оценщик, собрать
отдельный release и проверить его, затем переключить current. Прежняя V7
сохранена для отката. Ключ `/srv/sever/runs/.inference-evaluation.lock`
не удалять и не заменять. Новый API-файл меняет fingerprint; старые
закреплённые validation-batches продолжать под ним нельзя.

Проверки API/очереди/загрузок/доступа/замечаний: локально 149 passed;
после дополнительных проверок неполного охвата на сервере 151 passed.
Эти проверки не измеряют точность модели. Фактические проверки внешнего
входа и свежего браузерного запуска фиксируются в
`analysis/customer-trial-proof.json` и
`/srv/sever/validation/customer-portal-smoke/`.

Reader `native-source-images-model-authority-v5.2`, схема `native-image-model-authority-v5.1`, агент `fresh-model-selected-source-crops-v4`. Код проверяет структуру/происхождение и согласие двух исходных кадров; joint engine v3 перечитывает спорную форму/поля по реальным изображениям, сохраняет исходные ответы. Семантических regex-фильтров заголовка, даты, номера и ролей нет; без Tesseract, отдельного классификатора и replay |
| Исторический OCR | Tesseract `rus+eng`, `TESSDATA_PREFIX=/opt/sever-tsl/tessdata_best`, workers: 4; используется только в явном `ocr_guided` и его тестах |
| Просмотр | Nginx `127.0.0.1:8081`, корень `/srv/sever/runs`, `/api/` проксируется в API |
| Входы | 11 полных видео в `/srv/sever/input`; SHA и список из Yandex в `/srv/sever/validation/download-provenance.json` |
| Выходы | UUID-каталог каждого задания в `/srv/sever/runs`; общий `index.html`, манифест и proof в каталоге batch |

| Замок inference / оценки | `/srv/sever/runs/.inference-evaluation.lock`; совместная блокировка на inference, исключительная на независимую оценку |

Настройки запуска модели берутся из [sever-model.service](sever-model.service):
GPU layers `all`, context 65536, один slot, flash attention, KV cache `q8_0`,
`image-min-tokens=1024`, `image-max-tokens=4096`, Jinja и `enable_thinking=false`. Изменение этих параметров
меняет условия сравнения: сохраняйте service/config/model hashes вместе с результатами.
Сохранённые ответы распознавания не используются для нового чтения. Новые
фактические вызовы модели должны быть видны в трассе каждого свежего задания.

В `native_image` неопределённый тип не запрещает чтение: `observed_form` и
буквальный `visible_text` сохраняются также для `unknown`. Для известных форм
`visible_text` содержит собственный заголовок/шапку, а буквальные строки ролей
и значений записываются в `field.evidence_text`; у `unknown` транскрипция шире.
Поддерживаются
четыре контрактных типа и их 19 полей. Тип и каждое принятое поле требуют
согласующихся доказательств из двух разных исходных кадров того же листа;
повороты и фрагменты одного кадра не считаются отдельными подтверждениями.
Дополнительные кадры выбираются из пригодного неповторяющегося пула без
фиксированного числа кадров на лист, в пределах общего бюджета.
Модель сама определяет форму и роли; значения проходят структурную проверку и
сверку буквальных чтений с учётом Unicode, регистра и пробелов. Для названий
организаций и адресов также учитываются оформление кавычек и точки сокращений;
разные слова и числа, например «корп.» и «соор.», остаются разными чтениями.
Семантического отбрасывания программными правилами нет. Исходное значение и статус сохраняются;
отдельное форматированное представление не меняет решение модели.
Агент получает один JPEG-контекст с длинной стороной до 1024 пикселей и может
запросить до восьми нативных PNG-фрагментов исходного кадра. Его цикл ограничен
восемью запросами, отдельный выбор поворота также учитывается в общей квоте.
Последний запрос предназначен для `submit_reading`; лишний запрос фрагмента
получает явный `no_image` и записывается как отказ. Все участки и повороты этого
кадра остаются одним источником доказательств. При неопределённом повороте или
ошибке его схемы fallback читает реальные исходные панели новым вызовом;
fatal/provider и budget ошибки не скрываются fallback.
Отправленные пиксели, SHA, повороты и геометрия записываются в
`image-reading-evidence/`. Это доказательства нового вызова, не кэш для replay.
Исторический reader V2 использовал контекстные изображения с длинной стороной
до 1024 пикселей и детальные фрагменты до 2400.

API, CLI, слепые диагностические tools и оценщик должны использовать один
постоянный файл замка. Не удаляйте и не заменяйте его inode во время работы.
API admission берёт совместную блокировку без ожидания; при оценке новый POST
получает HTTP 423 до постановки в очередь. Принятый worker ждёт совместную
блокировку и держит её на всю обработку, включая терминальный экспорт.
Недоступный файл замка получает честную ошибку, а не обход защиты. Замок
кооперативный: отдельные старые probes или прямые HTTP-вызовы модели, которые
не используют helper, должны быть остановлены до оценки.

Ключ внешнего провайдера для этого режима не нужен. Не запускайте
`configure_provider.py`: этот отдельный helper настраивает RouterAI.
`AgentConfig` в режиме `local` требует явно заданный loopback endpoint и
отклоняет remote URL; неправильная конфигурация не переключается автоматически
на RouterAI. `--base-url` драйвера означает API конвейера на **8080**, а не
endpoint модели на **8090**.

В режиме `local` прямое чтение `native_image` выбирается по умолчанию;
для воспроизведения прежней схемы укажите `HARNESS_DOCUMENT_READER=ocr_guided`.
Remote-режим по умолчанию сохраняет прежний `ocr_guided`. Его наличие в исходниках
и тестах не означает, что классификатор используется в новой схеме.

Это ручной эквивалент параметров уже работающего driver unit. Для

следующее видео. Общие пределы — 22000 попыток и 440 млн входных + выходных токенов;
на одно локальное задание выделяется не более 40 млн токенов и 2000 попыток,
с учётом остатка общего бюджета. Ориентация, каждый шаг агента и финальное
представление ответа учитываются как настоящие запросы. Фиксированного
ограничения кадров на лист нет. Каждый запрос задания
задаёт `refresh_cache=true`; V7 выполняет новое чтение независимо от наличия
исторических ответов. Проверка происхождения отклоняет replay-события.
Локальный вывод не тарифицируется внешним API; аренда сервера, GPU и электричество
в этих числах не учитываются. Ожидание одного задания — до 43200 с;
превышение времени опроса сохраняет существующий UUID и не создаёт новый запуск.

API принимает максимум 40 млн токенов и 2000 запросов на локальное задание;
в remote-режиме сохраняются пределы 500 тыс. токенов и 400 запросов,
превышение отклоняется до очереди.
Общий лимит batch остаётся отдельным пределом, а не умножается на число видео.

### Возобновление и диагностика

Для продолжения того же незавершённого batch повторите команду с теми же путями,
моделью, приоритетом, лимитами и тем же fingerprint API/reader/schema/кода.
Изменённая версия не может продолжить старый пакет: требуется новый batch.
Завершённые задания не отправляются повторно:
это продолжение запуска, а не новое распознавание из сохранённых ответов.
Активный UUID сохраняется и опрашивается. Один
batch-каталог защищён lock от второго драйвера. Используйте ту же учётную запись,
которая создала batch; root-created batch не возобновляйте пользователем `sever`
без согласованного исправления прав.

Если ответ POST потерян, драйвер ищет уже созданное задание по исходнику и
сохранённому списку существовавших UUID. Неоднозначность получает
`submission_unknown/needs_attention`; новый платный/вычислительный запуск не
создаётся автоматически. `waiting_for_api` и `waiting_for_job` сохраняют UUID.
Отсутствующий ответ модели не означает нулевые токены: резервируется оставшаяся
квота задания. При `budget_exhausted` оставшиеся видео явно не обработаны.

```bash
systemctl status sever-model sever-tsl
journalctl -u sever-model -n 100 --no-pager
journalctl -u sever-tsl -n 100 --no-pager
```

Не удаляйте `manifest.json`, `job.json`, трассы или checkpoints ради повторного
старта. Для отдельного повторного эксперимента используйте новый batch-каталог.

## Смена модели и сравнение

Перед сменой модели остановите finish-controller, затем batch-драйвер.
Менять модель следует только когда нет активного драйвера и ни одного
`queued/processing` API-задания. Контекст, режим чтения, код, набор входов и ограничения
сохраняйте одинаковыми для сравнения; измеряйте реальное время и правильность,
а не только скорость токенов.

Проверить сохранённые активные задания можно без вывода документов или ключей:

```bash
python3 -c 'import json; from pathlib import Path; rows=[json.loads(p.read_text()) for p in Path("/srv/sever/runs").glob("*/job.json")]; print(json.dumps([{ "job_id": r.get("job_id"), "status": r.get("status") } for r in rows if r.get("status") in {"queued", "processing"}]))'
```

Список должен быть пустым; драйвер также должен быть остановлен, чтобы не
поставить следующее задание между проверкой и сменой модели.

```bash
systemctl stop sever-tsl
cp -a /etc/sever-tsl/local-model.env /etc/sever-tsl/local-model.env.previous
cp -a /etc/sever-tsl/local-provider.env /etc/sever-tsl/local-provider.env.previous
editor /etc/sever-tsl/local-model.env
editor /etc/sever-tsl/local-provider.env
systemctl restart sever-model
curl --fail http://127.0.0.1:8090/health
curl --fail http://127.0.0.1:8090/v1/models
systemctl start sever-tsl
curl --fail http://127.0.0.1:8080/health
```

В первом env меняются проверенные `MODEL_PATH`, `MMPROJ_PATH`, `MODEL_ALIAS`;
во втором оба alias (`HARNESS_MODEL_NAME`, `HARNESS_VISION_MODEL`) должны совпасть
с загруженной моделью. `HARNESS_PROVIDER_KIND=local` и loopback URL сохраняются.
Новый эксперимент получает новый batch-каталог и matching `--model`.
Изменение модели внутри существующего манифеста отклоняется. Для возврата
восстановите предыдущие env и перезапустите службы, также только при idle.

## Артефакты и смысл доказательств

`/srv/sever/runs/index.html` показывает фактический прогресс. Batch-манифест
содержит источники/SHA, настройки, UUID, статусы, общий расход и ошибки.
В UUID-каталоге доступны `results.json`, `fields.csv`, `report.html`,
`report-assets/`, `selected-pages.json`, `classifications.json`, исходные кадры,
`image-readings/`, `image-reading-evidence/` и `trace.jsonl`. Имя
`classifications.json` сохраняется для совместимости: в `native_image` это
решение из общего чтения изображения, без отдельного вызова классификатора.
`image-reading-evidence/` содержит отправленные JPEG-контексты, нативные
PNG-фрагменты и отдельные записи выбора поворота, новых ответов и отказов tools;
рядом записываются их SHA, геометрия, модель, схема, новый ответ и структурная
проверка. Эти записи только сохраняются, для распознавания не перечитываются.
`image-reader-cache/` относится к прежним сборкам и остаётся в старых результатах.
Отчёт загружает JPEG-превью и даёт ссылки на полноразмерные исходники;
`unknown` отображается как «Форма не подтверждена», с видимым названием формы
и буквальным текстом модели для каждого кадра, а также сохранёнными ошибками.
В отчёте показаны отдельные таблицы предложенных моделью полей каждого
фактически прочитанного кадра. Они не объявляются итоговым подтверждением
без согласующегося чтения второго исходного кадра.
В трассе новой схемы фиксируются `local_ocr_used=false` и
`separate_classifier=false`; сохранённые старые OCR-артефакты относятся к истории.
После каждого фактического чтения и завершения листа сохраняются
`partial-results.json` с источником, статусом и elapsed, а также
промежуточный отчёт с явным статусом «Обработка продолжается», без ссылки
на финальный CSV и с обновлением каждые 10 секунд. При сбое он показывает
«Обработка остановлена», сохраняет промежуточные чтения и не обновляется
автоматически. Три последовательные операционные ошибки листов сохраняют
все три листа/ошибки в failed checkpoint и остановленном отчёте до прекращения
задания. Финальный отчёт публикуется только после завершения экспорта.
`proof/<UUID>.json` сохраняет SHA результатов/трассы, source binding,
состояние исторических caches, события модели и проверки происхождения.

Для локального вывода каждый сохранённый `model_response_received` должен иметь
`provider_kind=local`, loopback `model_base_url` и billing `local_inference`:
`value=0`, `currency=null`. Несоответствие отмечается в proof и останавливает
дальнейшие задания. `fresh_run_verified=true` означает пройденные проверки
происхождения, а не верные реквизиты. `local_provider_verified=null` при нуле
ответов не доказывает execution модели. Промежуточная обработка без полного
экспорта не объявляется завершённым результатом.

Координаты native-доказательств относятся к действительно переданным изображениям
или фрагментам исходного кадра; `region_index=null`. Границы отдельных слов не
заявляются найденными OCR. Новый native-конвейер пока не предоставляет отдельно
подтверждённые ИНН сторон для реестра: `inn_verification.status=not_performed`,
`configuration.verify_inn=false`, сверка ФНС не заявляется выполненной.

## Независимая оценка после обработки

Эталон предназначен для отдельного root-only размещения в
`/root/sever-validation/private/ground-truth-expanded-provisional.json`; API-пользователь
`sever` не должен его читать. Этот JSON предварительный: сотрудник «Север ТСЛ»
ещё должен проверить и согласовать значения, `customer_approved=false`.
Эталон размещён отдельно, mode 0600;
API-пользователь `sever` не имеет права его читать. Драйвер и inference его
не читают и не получают ожидаемые поля.

Исторические контроллеры V3, V4 и V6 остановлены; их неполные пакеты не становятся
завершённой проверкой. Текущий V7 использует отдельную root-only копию tools
в `/root/sever-validation/native-v7-tools` и постоянный controller unit
`sever-validation-native-v7-finish-20261011.service`. Его checkpoint
`/root/sever-validation/native-v7-evaluation/finish.json` проверен в состоянии
`status=waiting`, `evaluation_attempted=false`, `truth_loaded_before_idle=false`,
`model_or_api_calls=0`. Пакет из 11 видео активен; оценка ещё не запускалась,
эталон этим контроллером не открывался.
Контроллер не открывает эталон до терминального batch, остановки driver unit
и отсутствия активных/неопределённых API-заданий. Перед повторной проверкой
всех API UUID и неизменности манифеста он получает исключительную блокировку
`/srv/sever/runs/.inference-evaluation.lock` без ожидания. Она удерживается
во время чтения эталона, оценки и сохранения её итогов/ошибок. Совместная
блокировка активного inference не позволяет начать оценку; новый API POST
во время оценки получает 423, а уже принятый worker ждёт освобождения замка.
Это устраняет промежуток между проверкой простоя и началом оценки для всех
процессов, использующих тот же постоянный файл замка.
При budget/provider/driver failure необработанные исходники сохраняются явно.
Ручной эквивалент параметров уже работающего controller unit приведён ниже;
его нельзя запускать параллельно с unit. Для работы используются изолированная
копия tools и интерпретатор конкретного release V7:

```bash
cd /root/sever-validation/native-v7-tools
PYDANTIC_DISABLE_PLUGINS=__all__ \
  /opt/sever-tsl/releases/20261011-native-image-v7/.venv/bin/python -B \
  /root/sever-validation/native-v7-tools/finish_server_validation.py \
  --manifest /srv/sever/runs/batches/native-image-qwen38-v7-20261011/manifest.json \
  --truth /root/sever-validation/private/ground-truth-expanded-provisional.json \
  --out /root/sever-validation/native-v7-evaluation/finish.json \
  --driver-unit sever-validation-native-v7-q38-20261011.service \
  --inference-gate /srv/sever/runs/.inference-evaluation.lock \
  --poll-seconds 10 --wait-timeout 604800
```

Контроллер сохраняет точный SHA/копию манифеста и отдельные checkpoint/evaluation
JSON. Оценщик вызывается один раз; таймаут или сбой не становится успешной
оценкой. Он не запускает задания и не вызывает модель/API. Его вывод находится
вне UUID-каталогов inference, а эталон — вне web root. Gate path и его протокол
закрепляются в checkpoint; старый вывод без такой привязки не используется для
незаметного продолжения оценки. Новый контроль получает отдельный output.

Оценка сопоставляет только четыре оригинальных полных видео по SHA и отдельные
завершённые API-результаты. Ещё семь видео без независимого эталона получают
`not_measured`: отсутствие разметки не превращается в ошибку распознавания.
У оригинального эталона 88 интервалов, 20 целевых интервалов, 44 размеченных поля
из 96 обязательных и 8 полностью размеченных целевых интервалов.

Сводка отдельно содержит метрики завершённых сопоставимых оригиналов и
консервативную оценку всех четырёх с необработанными исходниками как misses.
Историческая оценка читаемости macOS-кадров удаляется только из копии для расчёта:
для свежих Linux-кадров она не заявляется. Нормализованные значения, границы
интервалов и исходные результаты не редактируются. Операционные ошибки и расход
всех 11 заданий выводятся отдельно от знаменателей точности.

Исторические результаты короткого сравнения и УПД приведены выше. Фактические итоги
полного финального теста добавляются после его завершения и отдельной оценки;
пока они не заявляются. Новые проверки получают отдельный протокол. Договорная
приёмка ожидает проверки эталона сотрудником «Север ТСЛ» и его согласования
Заказчиком.
